# ai-red-teaming — monorepo

Two subsystems in one repo, coupled by the OpenAPI contract:

- **`backend/`** — Python/FastAPI API + Celery + Postgres + Redis. Has its own `CLAUDE.md`, `Makefile`, `.claude/skills/`. Work on it from `backend/`.
- **`frontend/`** — React/Vite operator console (typed client generated from the backend contract). Has its own `CLAUDE.md`, `Makefile`, `.claude/skills/`. Work on it from `frontend/`.

Each subsystem is self-contained — read its own `CLAUDE.md` before working in it. This file is only the map + cross-cutting glue.

## Running the whole stack (host needs Docker + make + uv)

One compose project, one network — the root `docker-compose.yml` `include`s both subdirs.

| Command (root) | Does |
|---|---|
| `make setup` | First run: backend deps/hooks/migrate/seed + frontend setup (+ creates `backend/.env` & `frontend/.env`) |
| `make dev` / `make up` | Whole stack (app, worker, beat, flower, db, redis, web, mailpit) — foreground / detached. Both `--build`, so a changed `pyproject.toml`/`uv.lock` (backend deps live in the image) is picked up automatically; the Docker layer cache makes it a no-op when nothing changed. |
| `make down` / `make logs` | Stop / tail the whole stack |
| `make gen` | Contract loop: refresh backend OpenAPI + regen FE client (backend up) |
| `make lint` / `make test` | Static checks / tests across both subsystems |
| `make check` | Full quality gate — `lint` + `test` |
| `make format` | Auto-format both subsystems |
| `make clean` / `make clean-dry` | `git clean` the whole repo / preview it (keeps `.env`/`.venv`/local settings) |
| `make be-<t>` / `make fe-<t>` / `make mon-<t>` | Delegate target `<t>` to `backend/`, `frontend/`, or `monitoring/` (e.g. `make be-migrate`, `make fe-gen`, `make mon-up`) |

Browser: FE `localhost:5173`, backend Swagger `localhost:8000/docs`, Flower `localhost:5555`, Mailpit inbox `localhost:8025`.

`make mon-up` / `make mon-down` bring the observability stack (Prometheus/Loki/Grafana/exporters/GlitchTip, normally deployed alongside `deploy/` — see [`monitoring/README.md`](monitoring/README.md)) up against this local stack instead, for testing the stack itself: Grafana at `localhost:3000`, Prometheus at `localhost:9090`, GlitchTip at `localhost:8090`. Requires the stack already up (`make dev`/`make up`). The box's `postgres-exporter` also has a local equivalent — `make be-upmonitoring` (then `make be-seedlocal` for the role it connects as).

> Frontend deps differ: `node_modules` is bind-mounted from the host, not baked into the image — so `--build` won't install them. After a `frontend/package.json` change run `make setup` (or `make fe-setup`).

## Contract loop (backend ⇄ frontend)

`backend/docs/openapi.yaml` is the single source of truth. After a backend API change:
`make be-openapidump` (refresh the committed spec) → `make fe-gen` (regenerate the typed client from the **live** backend `/openapi.json`, so it must be up) → fix the call sites the compiler flags. The committed `backend/docs/openapi.yaml` is consumed by the CI drift gate, which regenerates against it offline — local `make gen` hits the live server.

## Conventions

- **Compose project** is pinned via the compose `name: ai-red-teaming` (in each `docker-compose.yml`, not an env var), so root, per-subdir, and bare `docker compose` invocations all hit one stack. The root Makefile exports `DOCKER_UID/GID`, `BACKEND_URL`, and `COMPOSE_IGNORE_ORPHANS` for the run.
- Per-subsystem tooling, conventions, and skills live in `backend/` and `frontend/` — not here.
- **Git hooks are one root config for both subsystems** ([.pre-commit-config.yaml](.pre-commit-config.yaml), installed by `make be-install-hooks`). Backend hooks run on the host through `uv`; the frontend ones (`fe-eslint`, `fe-format-check`) shell out to `make -C frontend`, i.e. Docker. A `frontend/` change is therefore gated on ESLint + `prettier --check` at **push** time — run `make fe-format` before pushing. `make -C backend lint` deliberately `SKIP`s the two frontend hooks so the python-only CI `Lint` job never builds the FE image; note that no `make lint` variant runs Prettier — formatting is enforced by the push hook and CI only (`make fe-format-check` to check by hand).
- **PR size — soft ~400.** Keep each PR to roughly ≤400 lines of added/changed *production* code. Not counted: tests, docs, and generated artifacts (`uv.lock`, `backend/docs/openapi.yaml`, `backend/docs/erd.md`, `backend/docs/permissions.md`, Alembic autogenerate under `backend/alembic/versions/`, the FE typed client generated by `make gen`). A guideline with slack (±; ~460 is fine), **not** a hard gate and deliberately **not** a CI check — when a change clearly overshoots, split it into stacked PRs by layer (e.g. generic infra separately from its HTTP surface).
