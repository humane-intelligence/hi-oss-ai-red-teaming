## Rules for Claude

1. **Use `make` for every workflow.** Do not invoke `uv run pytest`, `uv run ruff`, `uv run ty`, `prek`, `alembic`, or `docker compose` directly. If a workflow is missing, add a Makefile target first, then call it. To narrow tests (single file/test/marker), use `make test ARGS='...'` — never raw `uv run pytest`. Exception: `uv add <pkg>`. **Migrations in particular must always go through make:** use `make makemigrations MSG='...'` to generate and `make migrate` to apply — never `alembic` or `docker compose run ... alembic` directly. **Makefile target names use no separators** — lowercase letters only, no `-` or `_` (e.g. `migrationsql`, not `migration-sql` or `migration_sql`).
2. **Tests:** read [.claude/skills/tests/SKILL.md](.claude/skills/tests/SKILL.md) before writing or modifying any test. pytest only. Test layout mirrors source — `tests/unit/` for pure logic, otherwise `tests/<area>/` matching `app/<area>/`. Tier is a marker (`unit` / `integration` / `e2e`), not a directory.
3. **Async by default** on I/O paths — FastAPI handlers, SQL, Redis, HTTP. Use `async def` and async clients unless the code is purely CPU-bound.
4. **Type checker is `ty`** (Astral), not mypy. Annotate public surfaces; let inference handle locals.
5. **Don't add deps casually.** Check `fastapi[standard]` extras and existing libs first. New top-level deps need a reason. **Always pin with `~=` at `major.minor` precision** (e.g. `~=2.13`, not `>=2.13` and not `==2.13.0`). After `uv add <pkg>`, manually tighten the specifier in `pyproject.toml` to `~=major.minor` if uv wrote `>=`.
6. **`pyproject.toml` is the single source of truth for tool config.** Don't introduce `setup.cfg`, `.flake8`, `mypy.ini`, etc.
7. **All datetimes are UTC.** Use `datetime.now(UTC)` (`from datetime import UTC`) — never `datetime.utcnow()` (deprecated, returns a naive datetime). DB columns are `DateTime(timezone=True)`. Never assume local time anywhere in the stack.
8. **KISS — no scaffolding on speculation.** Don't pre-create empty packages, placeholder modules, or "we'll fill it later" directories. Add a file when its first real content lands, not before. Exception: bounded-context packages under `app/core/` that are explicitly listed in the Architecture map below — they may exist as empty `__init__.py` placeholders to anchor the navigation map. Same rule applies to abstractions: don't add a base class, a registry, or a strategy pattern until the second concrete case shows up.
9. **Prefer functions over classes when there's no state.** A free function with typed arguments beats a class with a single method. Reach for a class when you have state to encapsulate, a protocol/ABC to satisfy, or genuine polymorphism — not for grouping helpers.
10. **Docstrings explain *why*, not *what*.** No `"""Fetch the user from the database."""` over `def fetch_user(...)`. Either say something non-obvious (a constraint, an invariant, a subtle behaviour) or omit it. Same rule applies to inline comments.
11. **Keep docs in sync — in the same diff.** When you change anything below, update the matching docs **in the same commit**. Doc drift is a bug; do not defer.

12. **Docstrings: Google Style for internals, Markdown for FastAPI routes.** Enforced by ruff `D200`/`D205`/`D212`/`D415`/`D417`/`D419` (see [pyproject.toml](pyproject.toml)).
    - **FastAPI route handlers** (`@router.<verb>(...)`): clean Markdown. First line is the high-level summary (FastAPI uses it as the Swagger summary). Optional Markdown body — e.g. `### Errors`, `### Implementation Notes`. **No `Args:` block** — types are auto-documented via Pydantic/FastAPI.
    - **Everything else** (services, helpers, models, schemas, middleware): Google Style. Summary line always; add `Args:` / `Returns:` / `Raises:` only when they carry information beyond the type hint (units, constraints, edge cases, non-obvious return shape, exceptions).
    - **`D417` rule:** if you write an `Args:` block, it must list every signature arg. Document **all args or none** — partial `Args:` fails lint.
    - **Module docstrings** stay tight and focus on the *why* / gotchas, not the *what*. Don't normalize existing module docstrings just to fit a template.
13. **Inference params: persist through `dump_inference_params`, never raw `model_dump`.** Every carrier of the `parameters` JSONB column (`AiModel`, `Evaluation`, future `Scenario`) shares one write contract from [app/core/ai_gateway/inference_params.py](app/core/ai_gateway/inference_params.py):
    - Serialize the edge `InferenceParams` via `dump_inference_params` (`exclude_none`) so storage holds only the knobs a level actually overrides — never a `null`. On a partial update, dump from the model, not the `exclude_unset` payload dict (that form keeps a `null`-valued knob).
    - The cascade is **two-state** (see `merge_inference_params`): a key present overrides, a key absent inherits. There is no "clear one knob" state, and an omitted `parameters` on a PATCH means *leave unchanged* — never reset to `{}`. Guard update paths with `if payload.parameters is not None:`.
    - `AiModel.advanced_params_disabled` opts a model out of the cascade entirely. Enforced in **one** place — `_build_call` in [dispatch.py](app/core/ai_gateway/dispatch.py), which every provider call funnels through — so a new param source upstream cannot bypass it. Reads that advertise inheritable params (`EvaluationAiModelView.effective_parameters`) project empty for such a model.
    - **Never merge gateway-owned context into `params`.** Anything the platform itself adds to a call (the conversation tag block, the health probe's token cap) must travel on its own channel — `dispatch_*`'s `system_suffix`, or applied after `_build_call` — because `params` is what the flag above suppresses. Folding tag context into `params["system_prompt"]` would silently drop it for a flagged model while the reply still recorded that context as sent.

## Architecture

- [app/main.py](app/main.py) — FastAPI app instance (`app`); applies the OpenAPI metadata from `app/core/openapi.py`, registers error handlers, wires routers via `app.include_router(...)`, and exposes Prometheus `GET /metrics` (prometheus-fastapi-instrumentator: HTTP RED + process metrics; probes excluded, route excluded from the OpenAPI schema, never proxied publicly). The Dockerfile and uvicorn command import this as `app.main:app`.
- [app/api/](app/api/) — HTTP route modules. Top-level files expose probes (e.g. [app/api/health.py](app/api/health.py) for `/health` and `/ready`, [app/api/version.py](app/api/version.py) for the public, unauthenticated `/version` — deployed commit SHA + environment). Domain endpoints live under [app/api/v1/](app/api/v1/) and are mounted with prefix `/api/v1` from [app/api/v1/__init__.py](app/api/v1/__init__.py). Conventions live in [.claude/skills/api/SKILL.md](.claude/skills/api/SKILL.md); [app/api/v1/auth/users.py](app/api/v1/auth/users.py) is the closest working reference.
- [app/core/](app/core/) — domain logic, organized into one submodule per bounded context (detailed below); add new implementation files alongside the existing `__init__.py`:
  - [app/core/logging.py](app/core/logging.py) — structlog + stdlib unified pipeline. `configure_logging(settings)` is called once from `app/main.py`; modules get a logger via `get_logger(__name__)`. Driven by `LOG_LEVEL` and `LOG_FORMAT` (`json` for prod, `console` for dev). JSON lines follow the log-shipping convention: message key `message` (renamed from structlog's `event`) plus a `service` field from `SERVICE_NAME` (default `ai-red-teaming-api`; compose sets `ai-red-teaming-worker` on worker/beat).
  - [app/core/middleware/](app/core/middleware/) — ASGI middlewares wired in `app/main.py` via `app.add_middleware(...)`. One file per middleware; `__init__.py` re-exports the public classes. Current:
    - [app/core/middleware/logging.py](app/core/middleware/logging.py) — `LoggingMiddleware`: binds `request_id` (`uuid4().hex`) / `method` / `path` into `structlog.contextvars` per request, echoes the id in the `X-Request-ID` response header, and emits one `http_request` access log per request with `status_code` and `duration_ms` (status defaults to 500 on unhandled exceptions). Inbound `X-Request-ID` is ignored — add upstream trust only once a sanitizing edge proxy is in front.
  - [app/core/config.py](app/core/config.py) — Pydantic `Settings` (env-driven) plus a cached `get_settings()` accessor. Exposes `database_url` and `redis_url` properties. Pool tuning via `DB_POOL_SIZE`, `DB_MAX_OVERFLOW`, `DB_POOL_TIMEOUT`, `DB_POOL_RECYCLE`, `DB_ECHO` (all optional with sane defaults). `.env` is auto-loaded; see `.env.example`.
  - [app/core/database.py](app/core/database.py) — Async SQLAlchemy engine (`build_engine`), module-level `_engine` / `_session_factory` singletons (set by lifespan in `main.py`), `get_db` FastAPI dependency. Models use `SQLModel` (from `sqlmodel`) as their base — see docstring for the pattern.
  - [app/core/base_model.py](app/core/base_model.py) — `BaseModel(SQLModel)`: abstract base for all primary table models. Provides `id` (UUID PK), `created_at`, `updated_at`, `deleted_at`, `deleted_by_id`. Subclass with `table=True` to create a table.
  - [app/models.py](app/models.py) — Central model registry. Import every new model module here; Alembic and any tooling needing the full schema import this single file.
  - [app/core/dependencies.py](app/core/dependencies.py) — `Annotated[X, Depends(...)]` aliases: `SettingsDep`, `DbSession`, `PaginationDep`. Add new wrappers here, not inline in routes.
  - [app/core/schemas.py](app/core/schemas.py) — shared request/response models: `Problem` (RFC 7807), `Page[T]`, `PaginationParams`.
  - [app/core/pagination.py](app/core/pagination.py) — `paginate(session, statement, *, limit, offset)` runs a count + page query against a filtered+ordered `Select` and returns `(items, total)`. Pair with `Page[T]` at the route layer.
  - [app/core/bulk.py](app/core/bulk.py) — platform contract for bulk endpoints: `BulkRequest[T]`/`BulkResponse[R]` schemas + `apply_bulk(session, request, processor)` helper. Per-row savepoint, partial success, `dry_run` rolls back instead of committing. Handlers using it must NOT decorate with `@transactional`. See [.claude/skills/api/SKILL.md](.claude/skills/api/SKILL.md) "Bulk endpoints".
  - [app/core/exceptions.py](app/core/exceptions.py) — `APIError` hierarchy (`NotFoundError`, `ConflictError`, …). Routers raise these instead of `HTTPException`.
  - [app/core/error_handlers.py](app/core/error_handlers.py) — `register_error_handlers(app)` installs handlers that translate `APIError`, `RequestValidationError`, `HTTPException`, and unhandled `Exception` into `application/problem+json` responses. Public `api_error_to_problem(exc, *, instance)` maps a single `APIError` to a `Problem` envelope; used by the handler and by `app.core.bulk` for inline per-row errors.
  - [app/core/openapi.py](app/core/openapi.py) — central OpenAPI metadata: `APP_TITLE`, `APP_SUMMARY`, `APP_DESCRIPTION`, `CONTACT`, `LICENSE_INFO`, `OPENAPI_TAGS`, plus `COMMON_ERROR_RESPONSES` (minimal 422/500 baseline) and the `problem_response(description)` helper for opting into per-route codes (404, 409, …).
  - [app/core/auth/](app/core/auth/) — identity and access: authentication and authorization. Platform-wide RBAC (the JWT-carried permissions) lives in [app/core/auth/roles.py](app/core/auth/roles.py). **Per-object roles** are a generic, second authorization scope in [app/core/auth/object_roles/](app/core/auth/object_roles/) (the django-guardian analogue): assign canonical roles to a user on a specific object via the polymorphic `ObjectRoleAssignment` table (`object_type` + `object_id`, no FK to the target). A held object role grants its own `Role.permissions` (the synced field) — there is no second permission vocabulary; `registry.py` (`ObjectType`, `ObjectScopeSpec`, `OBJECT_ROLE_REGISTRY`) holds only object-type *policy*: the assignable role set and the break-glass `super_permission`. `resolver.py` defines the rule — object roles are the only source of object authority: **break-glass** (a JWT-carried `super_permission` keeps full control) → a **held object role** is authoritative (an explicit role can only *narrow* power) → a **non-member gets nothing** (a global permission-holder has no say over an object they don't own/aren't a member of). Object *ownership* (the creator) is an additional write path applied by the gate. `service.py` is the assignment store + `resolve_object_access` (the gate input). Object visibility/ownership stays with the owning domain — this layer never loads the target object. **Restore:** `POST /api/v1/roles/{role_id}/restore` and `POST /api/v1/auth/users/{user_id}/restore`, each with `?deleted=true` on its list (`roles:manage` / `users:delete`, both showing every actor's deletes — there is no owner tier below either). A role comes back with its permission set and activation state untouched (holders regain access on their next token, as with any grant); a **system** role is refused (400) since `syncroles` recreates the name rather than reviving the tombstone, and the roles deleted view must pass `include_inactive=true` or a deactivated role's tombstone stays hidden. A user comes back with roles, status and org membership as the delete left them, behind the same elevation guard as the delete (`assert_can_restore_user` — restoring an admin needs `users:manage_admin`); the `provider_identities` the delete cascaded to stay tombstoned and the next external login re-links them (their unique index is partial), and no session is revoked either way, so an unexpired token minted before the delete works again. `ObjectRoleAssignment` deliberately has **no** restore endpoint: the row carries no state beyond `(object, user, role)`, so re-adding the member is the undo — and it re-validates the roles, which a restore would bypass.
  - [app/core/organizations/](app/core/organizations/) — the tenancy root. `Organization` ([models.py](app/core/organizations/models.py)) is a flat admin-managed entity (name + description). Membership is a single **nullable** `User.organization_id` FK (one user, one org; `ondelete="SET NULL"`) — orgless accounts (self-signup, legacy) are valid and stay platform-wide in scope. The org is carried in the session JWT (`SessionUser.organization_id`, frozen at mint like `permissions`) and surfaced live on `/auth/me` and `UserResponse` as a nested `OrganizationBase` (id + name), resolved from the DB via the `User.organization` relationship. A **soft-deleted org reads as no organization** — the projection guard `OrganizationBase.from_optional_live` is the authoritative rule (a many-to-one `with_live` doesn't reliably filter across identity-map states). CRUD + member assignment under [app/api/v1/organizations.py](app/api/v1/organizations.py) (`/api/v1/organizations` + nested `/{organization_id}/members`); the service ([services/organizations.py](app/core/organizations/services/organizations.py)) is plain CRUD plus `assign_member` / `remove_member` (stamp/clear the FK — no object-role machinery). Gated on the `organizations:read|create|update|delete|manage_members` split: **`read` is held by every role** (any user can list/view orgs); the management permissions (create/update/delete/manage_members) are **admin-only**. `EvaluationGroup` carries a nullable `organization_id` FK (added in Stage 1 so the whole tenancy schema is one migration). **Stage 2** wires it to read-visibility via the `EvaluationGroupAccessLevel.ORGANIZATION` access level (a third axis beside `public` / `invitation_only`): an `organization` group is visible only to members of its org, resolved from the caller's **live** org (not the frozen JWT) inside the single SQL chokepoint `group_visible_to` ([app/core/evaluations/access.py](app/core/evaluations/access.py)) and its in-Python mirror `group_is_visible` — so all ~14 read paths (groups + the `join_visible_evaluation_group` descendants) narrow with no per-call-site change. Fail-closed: a soft-deleted caller-org or group-org reads as orgless and stops matching. `organization_id` is **not** create-defaulted (set explicitly; create/update validate that `organization` access requires a live org). A non-admin may assign a group only to their **own** live org (cross-tenant planting is a 403; the `evaluation_groups:manage` break-glass lifts it), and **deleting an org is blocked (409) while any live group still references it** — a soft-delete doesn't fire the FK `SET NULL`, so the reference would otherwise leave those groups dark *and* un-editable (every group write re-validates a live `organization_id`); the create/update org-liveness check takes a `FOR SHARE` row lock so a concurrent delete can't open a TOCTOU window. A `public` group stays platform-wide regardless of any org. Cross-org sharing still rides the object-role layer (a held in-group role grants visibility at any access level). **Restore:** `?deleted=true` on the list (403 without `organizations:delete`; every actor's deletes, no owner tier) + `POST /api/v1/organizations/{organization_id}/restore`, 409 if a live org took the name. The flag is anchored to a single `conversation_id` and references an explicit **set** of that conversation's messages through the `flagged_messages` link table (`FlaggedMessage`, a plain composite-PK association row, not a `BaseModel` — its lifecycle is bound to the flag), so a user can flag any subset (one message, a range, or the whole conversation), and a conversation can carry many independent flags. The ancestry beyond the conversation is **denormalised** (`evaluation_id` / `evaluation_group_id` / `scenario_id`, plus an optional `task_id`) — resolved once at create (`resolve_conversation_context`) under the caller's ownership/visibility so it can't drift, after which every read needs only the flag's own columns. `status` (`FlagStatus`: pending/approved/rejected) lands `pending`; the reviewer-verdict workflow (multiple reviewers, per-reviewer verdicts, status transitions) is a **separate deferred scope** — there is no transition endpoint here, and the `flags:review` permission is not minted yet. Flat owner-scoped CRUD under [app/api/v1/message_flags.py](app/api/v1/message_flags.py) (`/api/v1/message-flags`): the service ([services/message_flags.py](app/core/annotations/services/message_flags.py)) scopes every read/write to `created_by_id == caller` **and** the parent group's visibility via the shared `join_visible_evaluation_group`, additionally joining the denormalised `conversation_id` through a live `Conversation` — so soft-deleting any ancestor (incl. the conversation cascades wired for model-unassign/delete) hides the flag with **no dedicated cascade hook**. The `evaluation_groups:manage` break-glass lifts both the owner and visibility predicates on read/update/delete — **but not on create**: authoring is owner-only (`resolve_conversation_context` requires `Conversation.user_id == caller`), so a manager can review and act on others' flags but never stamp one in their name (the flag is attributed to its author and owner-scoped reads would otherwise hide a manager-authored flag from the conversation owner). Gated on the `flags:read|create|update|delete` split: `red_teamer` + `admin` hold the full CRUD set, and `annotator` holds `flags:read` only (it reviews flagged outputs; `flags:review` lands with the deferred verdict workflow). Create validates the conversation is reachable, that every `message_ids` entry is a live message of it (a superseded-but-live message stays flaggable for provenance), and that `task_id`, when given, belongs to the conversation's scenario (all mismatches read as 404); the message set is immutable (only the content `reason` / `red_flagged` / `comment` is editable — to change the selection, create a new flag). The `message_id` list filter matches flags whose selection includes that message (an `IN`-subquery against the link table). **Restore:** `?deleted=true` lists the caller's tombstones inside `RESTORE_WINDOW_DAYS` and `POST /api/v1/message-flags/{flag_id}/restore` revives one (audited as `flag.restore`), scoped to `deleted_by_id` unless the break-glass lifts it. The module's **second entity** is `Note` ([models.py](app/core/annotations/models.py)): an annotator's free-text remark on a selection of one conversation's messages, with flat CRUD under [app/api/v1/notes.py](app/api/v1/notes.py) gated on the `notes:read|create|update|delete` split. Reads and the by-id writes are author-scoped with `evaluation_groups:manage` as the break-glass, but **authoring is not** — it requires only that the conversation's group is visible, so an annotator can leave a note on a red-teamer's transcript (`resolve_note_conversation`, the one deliberate divergence from the flag path). **Restore:** `?deleted=true` lists the caller's tombstones inside `RESTORE_WINDOW_DAYS` and `POST /api/v1/notes/{note_id}/restore` revives one (audited as `note.restore`), scoped to `deleted_by_id` unless the break-glass lifts it. The entity was renamed from `Annotation` so the name is free for the per-message label entity; the **package** keeps the `annotations` name, since it is the domain root for flags, notes, completions and those labels. The module's **third entity** is `Annotation` ([models.py](app/core/annotations/models.py)): the per-message label — one row per **(message, label, author)**, anchored to a single `message_id` rather than a selection, always referencing an `AnnotationLabel` (there is no free-text column: typing a label creates or reuses one scoped to the author, see the label bullet below), with the same denormalised ancestry and live-parent join as its siblings. Flat CRUD under [app/api/v1/annotations.py](app/api/v1/annotations.py) gated on the `annotations:read|create|delete` split — **no update key exists**: a tag has no editable content, so changing the label is delete + re-create. It **inverts the note asymmetry**: authoring likewise needs only group visibility (`resolve_annotation_message`, walking `message → turn → conversation`), but **reads are shared** — `join_conversation_scoped(..., author_scoped=False)`, the one sanctioned divergence in that shared authorization home, because a tag exists to be aggregated. Deletes stay author-scoped and refuse a foreign row with **403, not 404** (`assert_may_delete_annotation`): the wider read scope already made the row's existence public, so a 404 would lie. Dedup is one **partial unique** over live rows — `(message_id, label_id, created_by_id)` — so re-annotating identically returns the existing row (idempotent, the task-completions precedent) and a soft delete frees the slot; a restore that finds the slot retaken reads as **409**. Case folding lives on the label row, not here: a typed label resolves to the author's single entry before it reaches this table. `AnnotationResponse` **embeds** the label rather than referencing it, and the relationship deliberately omits `with_live(...)`: a retired label leaves the picker but must keep rendering on the rows that carry it. Held by `annotator` + `admin` (full) and `owner` (read only); the **red teamer holds nothing**, so labels on their own output are invisible to them. **Restore:** `?deleted=true` lists the caller's own tombstones inside `RESTORE_WINDOW_DAYS` — the restore surface stays personal even though live reads are shared — and `POST /api/v1/annotations/{annotation_id}/restore` revives one (audited as `annotation.restore`). The module's **fourth entity** is `AnnotationLabel` ([models.py](app/core/annotations/models.py)): flat reference data, anchored to no conversation, in **two kinds distinguished by `created_by_id`** exactly as `DataLicense` distinguishes its own — with a `CHECK` (`(created_by_id IS NULL) = (key IS NOT NULL)`) making the split a database fact rather than a convention the partial indexes cannot span. **Curated** (`NULL`) is the shared vocabulary, code-owned ([label_catalog.py](app/core/annotations/label_catalog.py), `CuratedAnnotationLabel`, deterministic row id via `curated_label_id` = `uuid5(namespace, key)`) and reconciled by `sync_annotation_labels` ([services/annotation_labels.py](app/core/annotations/services/annotation_labels.py), an idempotent upsert keyed on that id; a deploy step after `migrate` + part of `seedlocal`, `make syncannotationlabels`) — the curated-data-licence pattern, with `key` (not the display `name`) as the identity so rewording keeps the rows pointing at it. **User-scoped** (`created_by_id` set, no `key`) are created on demand by `find_or_create_user_label` when an annotator names a label new to them **and** absent from the curated set (typing a curated wording reuses that row, so picking and typing cannot diverge into two same-named labels on one message), deduped per author on `(created_by_id, lower(name))`; `sync_annotation_labels` **refuses** to write a wording another live row already holds (a typed label, or a curated row the catalog no longer names), which is one route to it, not the only one — two catalog entries agreeing up to case are both shipped ids the guard skips (only `test_annotation_label_catalog` catches those), and hand SQL and the guard's own unlocked scan/upsert window remain — **folded in Postgres, never Python**, which disagree on dotted capitals. So a wording the catalog does not hold persists as *that annotator's* entry rather than being retyped per message; one the catalog does hold resolves to the shared row instead. `GET /annotation-labels` returns curated ∪ the caller's own ∪ (with `?conversation_id`) those already used in that conversation whoever typed them — so annotators on one transcript converge on a spelling — but **never** another user's pool wholesale, and each row carries `is_custom`. **One entry per folded wording**, since each annotator holds their own row for a spelling: the curated row wins, then the caller's own, then a colleague's, so `total` counts wordings rather than rows. Deliberately **not** the `GET /ai-models/labels` shape (distinct-over-usage): this vocabulary has to be prepared up front and carry a stable id an annotation can FK to, so it is a table.

  - [app/core/platform_settings/](app/core/platform_settings/) — the admin-tunable, platform-wide settings **singleton** (django-solo analogue). `PlatformSettings` ([models.py](app/core/platform_settings/models.py), one-row table enforced by the fixed sentinel PK `PLATFORM_SETTINGS_ID`) holds the knobs: `default_license_id` (FK → `data_licenses.id`, NOT NULL), `invite_only` (disable open self-signup — enforced as a blanket, enumeration-safe 403 in `register_user` and a refusal of OIDC first-login provisioning; existing accounts keep logging in, invited/pending ones still activate), `email_verification_ttl_hours` (verification-link lifetime, PATCH-bounded 1–8760), the **password policy** (`password_min_length` 8–128 plus `password_require_uppercase|digit|symbol`, all defaulting to the shipped behaviour — floor 8, no character classes), and **password-reset throttling** (`password_reset_cooldown_seconds` 0–3600, `0` disabling it, and `password_reset_max_per_day` 1–100) — the window is per account and measured against that account's own reset tokens, so the limit bounds per-inbox volume, not aggregate outbound (no edge limiter exists); **an admin-triggered reset is not throttled at all — it ignores both the cooldown and the cap, but its sends count towards them**, so enough of them silently disable the account's own “forgot password” for the rest of the window — deliberate (same inbox, same flood), and separating the two would need a source column on `password_reset_tokens`. `service.get_platform_settings` returns the row or a **transient instance** carrying the shipped defaults (`default_license_id` resolved from `Settings.platform_default_data_license`, `email_verification_ttl_hours` from its env default) — reads never persist; the row materializes on the first *effective* admin write (`update_platform_settings(**changes)`, an atomic upsert on the sentinel id whose INSERT arm carries every knob at its current effective value — the knob list is derived from the model as `SETTINGS_KNOBS` — and whose DO UPDATE arm writes only `changes`). Endpoints ([app/api/v1/platform_settings.py](app/api/v1/platform_settings.py)): `GET|PATCH /api/v1/platform-settings` gated `platform_settings:read` / `platform_settings:update` (both admin-only) — the PATCH validates licence refs via `validate_license_ref` from [app/core/licenses/](app/core/licenses/) (including the shipped default when the write materializes the row), audits only the actually-changed fields, and a no-op writes (and audits) nothing — plus the **unauthenticated** `GET /api/v1/platform-settings/public` (`signup_enabled`, the invite-only inverse, plus the nested `password_policy` — the reset-throttling knobs stay out; shared-cacheable for 30s) backing the login/registration screens. **Cascade** (Platform default → Group override → Evaluation override, most-specific wins; conversations inherit): `EvaluationGroup.data_license_id` and `Evaluation.data_license_id` are nullable FK overrides (NULL = inherit); the **effective** license is resolved at the projection layer by `resolve_effective_licenses` ([services/evaluations.py](app/core/evaluations/services/evaluations.py), one platform-default read + one batched `IN` query joining the parent group — no N+1; the join ignores the group's `deleted_at`: license lineage doesn't lapse with a tombstoned parent). `EvaluationGroupResponse` and `EvaluationResponse` each surface both `data_license_id` (raw override) and `effective_license` (the resolved license object); `ConversationResponse` carries only `effective_license`, inherited from its evaluation (conversations have no license column). Tri-state on `EvaluationGroupUpdate.data_license_id` / `EvaluationUpdate.data_license_id`: omitted = unchanged, value = set, explicit `null` = reset to inherit (excluded from `_reject_explicit_null` like `cover_image`); every create/update write path validates a non-null id references a live license via `validate_license_ref`. **Create-time default:** when the payload *omits* `data_license_id`, the group create derives one from `access_level` — `invitation_only` gets the curated `No license` sentinel (so its evaluations and conversations inherit "no licence" instead of the platform default), any other level derives NULL (inherit); an explicit `null` always inherits. A later `access_level` change re-derives only when the group carries no licence **and** the payload omits the field — an inheriting group never chose one, while a stored id (or an explicit `null` in the same PATCH) is a decision and is never rewritten. A derived id is checked with `assert_curated_license_synced` (**500** — `synclicenses` has not run; the caller never sent that id), not `validate_license_ref`. The sentinel can never be the platform default: rejected at boot by `is_selectable_platform_default` and on `PATCH /platform-settings` (**400**). The group-detail embed computes each child's cascade in-memory from the loaded parent (no resolver round-trip), and duplicating a group copies its `data_license_id`.

Rows are **immutable** — there is no update endpoint, because rewriting the text of a version users already accepted would change what they agreed to; correcting a typo means publishing the next version — which is no longer free: publishing is itself gated, so the admin accepts the flawed version before they can replace it. The **current** document is the newest `published_at`, derived rather than flagged so it cannot drift; that column is stamped from the application clock, not `created_at`, because Postgres `now()` is transaction-start time and two documents written in one transaction would tie with no way to break it. A sweep in [tests/api/v1/test_endpoint_guards.py](tests/api/v1/test_endpoint_guards.py) asserts both directions over every authenticated route. Strictly owner-scoped with **no** break-glass (another user's view is a 404) and a partial-unique `(created_by_id, resource, name)` among live rows. Router: [app/api/v1/saved_views.py](app/api/v1/saved_views.py); `saved_views:read|create|update|delete` are held by **every** role (personal data). **Restore:** `?deleted=true` + `POST /api/v1/saved-views/{view_id}/restore` within `RESTORE_WINDOW_DAYS`; there is no break-glass, so a tombstone is only ever the caller's own, and reviving a view whose `(resource, name)` a live one has since taken is a 409.
  - [app/core/audit/](app/core/audit/) — the append-only, FK-less trail of sensitive actions and accesses. Two write paths: mutating handlers call `record_audit(...)` ([service.py](app/core/audit/service.py)) inside their `@transactional` body, so the row commits atomically with the action (it returns the flushed row, so a handler owning its transaction can compensate); reads/accesses (login attempts, export downloads, transcript reads) are captured by the innermost `AuditAccessMiddleware` ([app/core/middleware/audit.py](app/core/middleware/audit.py)) on its own session, best-effort. `AuditAction` ([enums.py](app/core/audit/enums.py)) is a `domain.verb` catalog stored as **plain text**, so it grows without a migration; `before`/`after` are curated non-secret snapshots (`changed_fields` reduces them to what changed), never whole rows. Rows are never updated or soft-deleted and the table has no FKs, so the trail survives whatever it references. Read-only surface [app/api/v1/audit_logs.py](app/api/v1/audit_logs.py) gated on the admin-only `audit:read`.
  - [app/core/notifications/](app/core/notifications/) — a user's in-app notification feed (the console bell). `Notification` ([models.py](app/core/notifications/models.py)) is delivered to one `user_id` with a `name` / optional `description`, a `read_at` mark, and an optional **loose** `object_type` / `object_id` pointer (a plain string validated against `NotificationObjectType`, no FK — the target may be gone) so the client can deep-link. There is **no HTTP create**: rows are minted by `create_notification` ([services/notifications.py](app/core/notifications/services/notifications.py)), which flushes but never commits, so a notice lands atomically with the domain transaction that emitted it (a rolled-back verdict announces nothing). Emitters today: the evaluation approve/reject ([services/approval.py](app/core/evaluations/services/approval.py)) and group approve/request-changes/reject ([services/publication.py](app/core/evaluations/services/publication.py)) verdicts — both **skipped when the actor is the owner** (a self-verdict is not news) — plus export completion (`emit_export_completion`, which always notifies the requester) and the model-inactivity sweep ([services/inactivity.py](app/core/ai_gateway/services/inactivity.py), one per recipient). Router [app/api/v1/notifications.py](app/api/v1/notifications.py) (`/api/v1/notifications` + `/mark` + `/{id}`): strictly owner-scoped with no break-glass, `POST /mark` flips only rows in the opposite state (an empty `ids` means all of the caller's) and returns how many actually changed, and the unread count is `total` on `?read=false`. Gated on `notifications:read|update`, held by **every** role like `saved_views:*`; there is no create/delete member.
- [app/workers/](app/workers/) — Celery application and task infrastructure. `celery_app.py` builds the `Celery` instance from `Settings` and auto-discovers `tasks.py` modules under each `app/core/<domain>/` package. `session.py` exposes `session_scope()` — a sync SQLAlchemy session (psycopg v3 driver) that tasks must use for DB access; the async engine from `app/core/database.py` is unusable in worker processes. Reference patterns and conventions for adding a new task: [.claude/skills/tasks/SKILL.md](.claude/skills/tasks/SKILL.md).
- [tests/](tests/) — pytest suite. Mirrors the `app/` layout (e.g. [tests/api/](tests/api/) for route tests).

Configuration flows in one direction: env vars → `Settings` (via pydantic-settings) → `get_settings()` (cached). Do not read env vars directly elsewhere; add fields to `Settings` instead so the `.env` contract and Compose env stay in sync.
